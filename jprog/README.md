# JProg (`jprog/`, top-level - not under `src/lib/`)

Standalone Java desktop app used at the shop for sheet-stock nesting and
G-code generation/editing (the "Jprogged" stage in the manufacturing router,
see `src/lib/statuses.js`). Previously lived only on Google Drive
(`sources.txt` still has the old `G:\My Drive\frc971\...` paths); this
directory is that codebase brought into version control. It's an unrelated
tech stack from the rest of this repo (Java + a Python helper script, no
SvelteKit/Node), so it's kept in its own top-level folder rather than under
`src/lib/`, the same way `autocam/` is.

- **`Runner.java`** / **`JustinProg.java`** - entry points.
- **`Display/`** - Swing UI screens and dialogs.
- **`Parser/GCode/`** - G-code parsing/generation, with separate 971 and
  WinCNC dialect parsers (mirrors the `linuxcnc`/`wincnc` controller split in
  `autocam/routing.js`).
- **`Parser/Sheet/`** / **`SheetHandler/`** - sheet/part/cut/hole model and
  the sheet-layout file format read from `sheets/` (not committed - runtime
  data, see below).
- **`lib_files/`** - vendored Ruby geometry/gcode/DXF helper libs used by the
  parser.
- **`assets/holes/`** - canned hole-drilling G-code templates per metal
  thickness, referenced by path from `settings.json`.
- **`EndmillCalculator.py`** - standalone speeds/feeds helper script.

## Build & run

`build.sh` (macOS/Linux) / `build.bat` (Windows) copy the source into a temp
dir, `javac` compile `Runner.java` + `JustinProg.java`, run `java -cp ...
Runner`, then delete the temp build dir. No separate build/dependency step
needed beyond a JDK on `PATH`.

## Not committed

`parts_library/`, `output/`, `sheets/`, and `logger.log*` are runtime
data/logs generated by using the app (hundreds of MB), not source - see
`jprog/.gitignore`. The original Google Drive folder also had a
`LinuxCNC Computer Files/` directory (machine-controller drivers/manuals,
~11MB, unrelated to this app's own source) which was likewise left out.
